# OpenSERP batch search (CSV → JSON → merged JSON)

Requires **Python 3.10+** (standard library only) and a running OpenSERP API (e.g. `./deploy.sh status`). Execute commands from the repository root.

Create a UTF-8 CSV file containing **one search term per line**, with no header by default:

```csv
Python tutorials for beginners
Introduction to Docker
"Kubernetes, networking and Linux"
```

A quoted value can contain commas. If your CSV has a header, add `--header`. Empty lines are skipped. For searches, use:

```bash
python3 batch-search/search.py keywords.csv
# Prints output folder, e.g. batch-search/results/run-20261108-120000-1a2b3c4d
python3 batch-search/merge.py batch-search/results/<printed-run-folder>
```

**Defaults:** video search, `1080p`/Full HD keyword, `15 minutes` keyword, all six engines, and an OpenSERP request limit of **100 per engine per CSV query**. Calls use `GET /mega/search?mode=balanced&limit=100&dedupe=false&merge=true` so the API does not remove cross-engine duplicate results. The API can return fewer than 100 results per engine and may report CAPTCHA, rate limits, or timeouts. Video duration and quality are **search keywords only**, not verified media metadata. A batch can be long-running and resource-intensive; the default two-second pause between items reduces request bursts.

Other content modes:

```bash
python3 batch-search/search.py keywords.csv --type text
python3 batch-search/search.py keywords.csv --type all --engines google,bing --limit 50
python3 batch-search/search.py keywords.csv --type image
python3 batch-search/search.py keywords.csv --type video --quality 720p --min-minutes 30
python3 batch-search/search.py keywords.csv --api http://192.0.2.10:7000 --site youtube.com
python3 batch-search/search.py keywords.csv --header --output-dir ./my-new-batch
python3 batch-search/merge.py ./my-new-batch --output ./merged.json
```

`--type image` sends requests to `/mega/image`; image support varies by engine. `--type text`, `web`, and `all` all use regular web search with **no video modifiers**. `--quality ''` and `--min-minutes 0` disable video keywords. Options include `--delay`, `--timeout`, `--retries`, `--limit`, `--site`, `--engines`, and `--output-dir` (run `--help`).

## Output and recovery

Every invocation creates a **new run directory**; earlier files are never overwritten. It contains:

```
run-.../
  manifest.json       # original CSV rows, query settings, planned files
  item-000001.json    # full OpenSERP JSON for CSV item #1 + _batch context
  item-000002.json
  ...
  merged.json         # generated by merge.py
```

Each JSON retains OpenSERP's `results`, `query`, `meta`, and `engine_errors` (when supplied). The `_batch` field records the source CSV line and original input. When a request fails, its item JSON contains an empty `results` list and `batch_error`, and the search script exits with code **1** after processing the remaining items. HTTP 429/502/503/504 and transient network failures are retried once by default. Engine-specific partial failures in a successful API response are preserved in `meta.engines_failed`.

`merge.py` combines every planned item into one `items` array, preserving per-input OpenSERP JSON and a summary of results/errors by engine. It **does not deduplicate** results. It detects missing files (for example after Ctrl-C) rather than silently dropping them; use `--allow-partial` if you deliberately want a merge of completed items only. The merge operation does not make API calls. Existing merged output files are preserved unless you explicitly pass `--overwrite`. Results are excluded from Git by `batch-search/.gitignore`.

**Data protection:** CSV terms and search results remain in local JSON files. Do not commit batches containing sensitive search terms, private URLs, or proxy information. If the API is on another host, use its reachable URL and restrict network access appropriately.
